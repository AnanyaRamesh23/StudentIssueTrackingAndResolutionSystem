1. Multi-Table JOIN Query (5 Relational Tables)

INNER & LEFT JOIN

Combines ISSUE, STUDENT, CATEGORY, STATUS, and STAFF without data duplication.

SELECT i.Issue_ID, s.Name AS Student_Name, c.Category_Name, COALESCE(sf.Name, 'Unassigned') AS Staff_Name, st.Status_Name, i.Priority, i.Due_Date FROM ISSUE i JOIN STUDENT s ON i.Student_ID = s.Student_ID JOIN CATEGORY c ON i.Category_ID = c.Category_ID JOIN STATUS st ON i.Status_ID = st.Status_ID LEFT JOIN STAFF sf ON i.Staff_ID = sf.Staff_ID ORDER BY i.Issue_ID ASC LIMIT 6;

2. Aggregation with GROUP BY and HAVING Clause

GROUP BY & HAVING

Calculates average student satisfaction ratings per staff member, filtering only staff who have handled at least 2 issues using HAVING COUNT(i.Issue_ID) >= 2.

SELECT sf.Staff_ID, sf.Name AS Staff_Name, sf.Department, sf.Role, COUNT(i.Issue_ID) AS Issue_Count, ROUND(AVG(f.Rating), 2) AS Avg_Rating FROM STAFF sf JOIN ISSUE i ON sf.Staff_ID = i.Staff_ID LEFT JOIN FEEDBACK f ON i.Issue_ID = f.Issue_ID GROUP BY sf.Staff_ID, sf.Name, sf.Department, sf.Role HAVING COUNT(i.Issue_ID) >= 2 ORDER BY Issue_Count DESC;

3. Database View: v_staff_workload

SQL Views

Virtual table that encapsulates aggregation metrics (Assigned, In Progress, Resolved, Closed, Overdue) across STAFF, ISSUE, and STATUS.

CREATE OR REPLACE VIEW v_staff_workload AS SELECT sf.Staff_ID, sf.Name AS Staff_Name, sf.Department, sf.Role, COUNT(i.Issue_ID) AS Total_Assigned, SUM(CASE WHEN st.Status_Name = 'In Progress' THEN 1 ELSE 0 END) AS In_Progress_Count, SUM(CASE WHEN st.Status_Name = 'Resolved' THEN 1 ELSE 0 END) AS Resolved_Count, SUM(CASE WHEN st.Status_Name = 'Closed' THEN 1 ELSE 0 END) AS Closed_Count, SUM(CASE WHEN i.Due_Date < CURDATE() AND st.Status_Name NOT IN ('Resolved', 'Closed') THEN 1 ELSE 0 END) AS Overdue_Count FROM STAFF sf LEFT JOIN ISSUE i ON sf.Staff_ID = i.Staff_ID LEFT JOIN STATUS st ON i.Status_ID = st.Status_ID GROUP BY sf.Staff_ID, sf.Name, sf.Department, sf.Role;

4. ACID Transaction Demonstration (Issue Reassignment)

ACID Transactions

When an issue is reassigned, multiple operations execute inside an atomic transaction: UPDATE ISSUE.Staff_ID and INSERT INTO REASSIGNMENT_LOG. If either fails, the entire transaction is rolled back.

START TRANSACTION; -- Step 1: Update issue handler and transition status if necessary UPDATE ISSUE SET Staff_ID = p_new_staff_id, Status_ID = 2 WHERE Issue_ID = p_issue_id; -- Step 2: Write permanent audit record INSERT INTO REASSIGNMENT_LOG (Issue_ID, Old_Staff_ID, New_Staff_ID, Reassigned_On, Reason) VALUES (p_issue_id, v_old_staff_id, p_new_staff_id, NOW(), p_reason); COMMIT;

5. 1:1 Relationship & CHECK Constraints (FEEDBACK Table)

UNIQUE & CHECK

Enforces that each closed/resolved issue can have at most one feedback record (Issue_ID UNIQUE) and rating is between 1 and 5 (CHECK (Rating BETWEEN 1 AND 5)).

CREATE TABLE FEEDBACK ( Feedback_ID INT NOT NULL AUTO_INCREMENT PRIMARY KEY, Issue_ID INT NOT NULL UNIQUE, -- 1:1 Relationship constraint! Rating INT NOT NULL, Comments TEXT NULL, Submitted_On DATETIME DEFAULT CURRENT_TIMESTAMP, CONSTRAINT fk_feedback_issue FOREIGN KEY (Issue_ID) REFERENCES ISSUE(Issue_ID) ON DELETE CASCADE, CONSTRAINT chk_feedback_rating CHECK (Rating BETWEEN 1 AND 5) );

6. Relational Normalization Architecture (Up to 3NF)

3NF Normalized
  • First Normal Form (1NF): All attributes contain atomic, scalar values. Every table possesses an explicit primary key.
  • Second Normal Form (2NF): Achieved 1NF and no non-prime attribute depends on a partial key. Every table uses a single-attribute primary key, completely eliminating partial functional dependencies.
  • Third Normal Form (3NF): Achieved 2NF and strictly no transitive functional dependencies ($X \rightarrow Y \rightarrow Z$).
    • Student names, departments, and years are stored only in STUDENT.
    • Staff names, departments, and roles are stored only in STAFF.
    • Category names and default SLA days are stored only in CATEGORY.
    • Status descriptions are stored only in STATUS.
    • ISSUE only holds foreign key references (Student_ID, Staff_ID, Category_ID, Status_ID).
